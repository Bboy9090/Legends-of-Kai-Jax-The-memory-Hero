You didn’t “break Tailwind.” You’re just asking Vite (running in `client/`) to load a PostCSS config from the **repo root**, which then tries to `require('tailwindcss')` **at the root**… where it isn’t installed. So Vite screams.

Here’s the clean fix menu—pick ONE path and do it fully.

# Option A — Keep config at **root** (workspaces/monorepo style)

If `postcss.config.js` lives at `/home/runner/workspace/postcss.config.js`, then Tailwind, PostCSS, and Autoprefixer must be devDeps **at the root**.

**PNPM**

```sh
pnpm -w add -D tailwindcss postcss autoprefixer
pnpm -w dlx tailwindcss init -p
```

**Yarn (Berry)**

```sh
yarn add -D -W tailwindcss postcss autoprefixer
npx tailwindcss init -p
```

**npm (workspaces)**

```sh
npm i -D -w tailwindcss postcss autoprefixer
npx tailwindcss init -p
```

> Why this works: the root `postcss.config.js` resolves plugins from the root `node_modules`. Install them there and the error dies.

# Option B — Move config into **client/**

If this is a single-app repo (or you want `client` to be self-contained), move your config files next to the app.

```sh
# from repo root
mkdir -p client
mv postcss.config.js client/postcss.config.js  # if it exists at root
mv tailwind.config.{js,cjs,ts} client/         # if it exists at root
```

Then ensure `tailwindcss`, `postcss`, `autoprefixer` are devDeps **in `client/package.json`**:

**PNPM**

```sh
cd client
pnpm add -D tailwindcss postcss autoprefixer
pnpm dlx tailwindcss init -p
```

**Yarn / npm**: same idea but scoped to `client`.

Update configs when they live in `client/`:

**`client/tailwind.config.js`**

```js
/** @type {import('tailwindcss').Config} */
export default {
  content: ["./index.html", "./src/**/*.{js,ts,jsx,tsx}"],
  theme: { extend: {} },
  plugins: [],
};
```

**`client/postcss.config.js`**

```js
export default {
  plugins: {
    tailwindcss: {},
    autoprefixer: {},
  },
};
```

# Quick sanity checks (do these no matter which option you chose)

1. **`index.css`** has Tailwind directives at the top:

   ```css
   @tailwind base;
   @tailwind components;
   @tailwind utilities;
   ```
2. **Imported** once in your entry (e.g. `client/src/main.tsx` or `index.tsx`):

   ```ts
   import './index.css';
   ```
3. **Vite runs from `client/`**:

   ```sh
   cd client && pnpm dev
   ```
4. If CI is failing, install at the same scope you used locally:

   * Option A: install at **root** in CI (`pnpm -w i --frozen-lockfile`)
   * Option B: `cd client && pnpm i --frozen-lockfile`

# Bonus: why you saw the exact error

* `searchPath: /home/runner/workspace/client` → Vite looked for PostCSS config starting in `client/`.
* `Require stack: /home/runner/workspace/postcss.config.js` → It found your config **one directory up** (the root), which called `require('tailwindcss')`.
* Since `tailwindcss` isn’t installed **where that config lives**, Node couldn’t resolve it → boom.

Pick A (root-level deps) if this is a real monorepo. Pick B (move config into `client/`) if it’s a single app. Do it once, consistently, and the error’s gone. Want me to patch your configs in the canvas with your current file names? Say the word and tell me which option you’re choosing.
