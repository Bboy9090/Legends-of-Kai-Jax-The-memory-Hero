## What this release is

The first web-playable vertical slice of **Legends of Kai-Jax: The Memory
Hero**: a 15-mission, 3-act campaign playable start to finish through
Training Arena and Story Mode, with a working save/pause/quit loop and,
as of this pass, functional touch controls.

## Included in this MVP

**Core loop** (verified — see `README.md` §7 for the full breakdown):

- Main Menu, LoreHub (default landing screen), mission selection via the
  campaign map, and Adventure Mode gameplay (movement, light/heavy/skill
  attacks, dodge, combo chaining, auto-targeting).
- 15 story missions across 3 acts (5 each), verified by direct count in
  `apps/web/src/lib/story_missions.ts`.
- Pause / Resume / Force Quit, hardened with a persisted-state override
  and a final-resort reload fallback (Phase 1A work,
  `docs/qa/PHASE1A_PLAYTEST_2026-06-19.md`).
- Player-visibility fallback: if a character's GLB model fails to load,
  a guaranteed-visible capsule stand-in renders instead, so the player is
  never invisible.
- **Keyboard input** — the original, fully supported path (WASD/arrows,
  J/X, K/Z, L/C, Space, Esc/P).
- **Touch input — new in this pass.** Adventure Mode previously had zero
  functional touch input despite three different partial
  implementations existing in the codebase; none were correctly wired.
  A single new control surface
  (`apps/web/src/components/game/adventure/AdventureTouchControls.tsx`)
  now drives the same input path the keyboard already used: joystick
  movement, ATK/HEAVY/SKILL attacks, DODGE, and a pause button. Verified
  with a 14-check scripted multi-touch Playwright pass (movement,
  simultaneous movement+attack, pause/resume, force-quit, no stuck input
  after `touchcancel` or a full route exit) — see
  `docs/qa/PHASE1B_MOBILE_TOUCH_SMOKE_TEST_2026-07-17.md`.
- **Gamepad input is not included.** No `navigator.getGamepads()`
  integration exists anywhere in the codebase for this release.

**Fixed for this release** (each with a full audit trail in `docs/qa/`):

- Four route/navigation bugs: a soft-locking profile-select modal on the
  main menu, two guaranteed-404 links on the LoreHub landing page, no way
  to back out of a wrongly-picked mission, and a dead duplicate game-state
  store file that was one config change away from silently breaking every
  screen transition (`docs/qa/PHASE1B_ROUTE_AUDIT_2026-07-17.md`).
- LoreHub's hero/character/gallery art is now fully self-hosted — no
  production dependency on a temporary third-party asset host
  (`docs/qa/PHASE1B_EXTERNAL_ASSET_AUDIT_2026-07-17.md`).
- A broken `pnpm-lock.yaml` entry that caused `pnpm install
  --frozen-lockfile` to fail outright — fixed, so a clean CI/deploy
  install now works.
- A mobile-width layout bug (LoreHub's top nav overlapped at phone
  screen widths) — fixed.

## Known limitations at this release

Tracked in full in `docs/known-debt.md`. Headline items relevant to a
release decision:

- CI's automated "Test" step currently runs a placeholder, not the real
  test suite — a false-confidence signal in CI, not a product defect, but
  worth fixing before leaning on CI green as release proof.
- Two of LoreHub's six character/gallery images have no local source
  asset and currently show a branded placeholder icon instead of real
  art, pending an asset-sourcing decision.
- Two Tailwind spacing findings on LoreHub's mobile layout (a
  below-minimum CTA tap target, a missing gap in the hero button row) —
  cosmetic, don't block playability, not yet fixed.
- GLB tail-anchor coverage is incomplete on some character models
  (handled gracefully — the game degrades to limited tail attachment
  rather than failing).
- Full-repository TypeScript debt exists outside the Phase 0-scoped
  typecheck gate this MVP was verified against.
